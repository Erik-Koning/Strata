Strata

Layered memory for AI-assisted development.

Strata drafts short notes about your coding sessions: what was built, what was learned, how the work actually got done, where it slowed down, and what the agent had to guess. You review every note before anyone else sees it. Approved notes build up, layer by layer, into a shared picture of each product: what shipped, where engineering time goes, what nobody has written down, and an assistant that answers from all of it.

Design draft, November 2026. The capture plugin and memory API are built; records and the hub are next.

Five kinds of record

The agent drafts these at the end of a session, or logs one the moment it runs into it. All five go through the same review.

  • Summary

    drafted at session end

    What was implemented and why, in a few sentences, linked to the Jira ticket and GitHub PR behind it.

    Read by managers, PMs and teammates who want status without asking.

    ExampleAdded retry with backoff to the invoice sync worker; timeout now comes from config. PAY-412.

  • Insight

    drafted or logged live

    A fact about the system that the code doesn't make obvious: a constraint, a quirk, or a decision and the reason for it.

    Read by the next engineer and the next agent session.

    ExampleLedger rounds per line. Sum rounded lines, never round the invoice total.

  • Workflow finding

    drafted or logged live

    How work on this repo actually gets done: setup steps, test order, release steps, who approves what.

    Read by new joiners and analysts learning how a team works.

    ExampleRun docker compose up mongo before npm run test:int.

  • Pain point

    suggested

    Something that slowed the session down, written as a suggestion: a slow build, a flaky test, a missing script, a manual step that keeps coming back.

    Read by team leads and platform teams deciding what to fix.

    ExampleAdd a per-package test script. The full suite ran 4 times in one session.

  • Context gap

    logged live

    Information the agent needed and couldn't find, so it guessed, searched, or had to ask. Gaps that repeat across sessions point at the docs worth writing.

    Read by doc owners, and loaded into the next session so the agent knows what it doesn't know.

    ExampleWhy is the queue at-least-once? No ADR, no comment. Agent read 3 files to infer it.

Pain points and context gaps describe the codebase and the process. They never describe a person.

Nothing is shared without review

Until you approve a record, nobody else can see it.

  1. Capture

    Hooks capture your prompts, Claude's replies and how long each tool ran. Never a command's output.

  2. Redact

    Secrets, tokens and keys are stripped on your machine, and again on the server.

  3. Draft

    When the session ends, Claude drafts a summary and findings. Only you can see the draft. The session's redacted prompts and replies stay private to you and expire after 30 days.

  4. Review

    You approve, edit or discard each record, in the hub or with /strata:review.

  5. Share

    Approved records join the product's pages and are indexed for search.

Four layers, read from the top

Each layer rolls up the one below it. Most questions are answered from the top two layers, and the detail underneath is fetched only when someone drills down.

read firstdetail on demand

  1. Product overview

    one per product · rewritten each roll-up

    What the product is, where it stands, who knows it. The first thing a manager or new joiner reads.

  2. Ticket and PR

    one per Jira ticket or GitHub PR

    Approved session summaries rolled up and linked to the work item they belong to.

  3. Session

    one per coding session · reviewed

    The approved summary with its insights, workflow findings, pain points and context gaps.

  4. Session events

    many per session · private · kept 30 days

    Prompts, replies and tool timings, redacted. Raw material for the session draft, and nobody else's to read.

What the hub does

Five capabilities, built from approved records and from tool timings that carry no content. Every summary, figure and answer opens the records behind it. The examples use made-up data.

  • Product pages

    one per product

    Each product, made up of one or more repositories, gets a page that says what it is, what changed lately and what's in progress. Status without a standup, and without anyone writing a report.

    • What's new: recent features and changes in plain language, rolled up from approved session summaries and linked to their tickets and PRs.
    • In progress: open tickets and PRs with recent sessions, and the pain points slowing them down.
    • The product's own friction, open context gaps and slice of the knowledge graph.
    • Who has worked on each area recently, so you know whom to ask.
    • A weekly digest of the page for anyone who follows the product, and a home page across all products.

    For managers, PMs, and anyone who'd otherwise ask in a standup.

  • Where engineering time goes

    hours, ranked

    Time lost to slow, flaky and repeated work, ranked so the biggest leak is at the top, each with a suggested fix.

    • Measured from test, build, install and lint runs: how long each took, whether it failed, and how often it was run again.
    • The pain points in session drafts explain the cause and suggest the fix.
    • Grouped by product and repository, with the trend over recent weeks.
    • Every figure opens the sessions behind it.
    • File an item as a ticket, then check whether the hours fell after the fix shipped.

    For team leads and platform teams deciding what to fix next.

  • Context gaps

    agents and people

    What agents and people needed to know and couldn't find. The gaps that repeat are the docs worth writing first.

    • From agents: logged live when a session had to guess, search at length, or ask.
    • From people: questions the assistant couldn't answer, and gaps people log themselves with /strata:note.
    • Counted across sessions and people, so the gaps that keep coming back rise to the top.
    • Give a gap an owner, then resolve it by linking the doc, ADR or code comment that answers it.
    • Open gaps load into new sessions, so the agent knows what it doesn't know. A resolved gap brings its answer instead.

    For doc owners and tech leads, and for the next agent session.

  • Knowledge graph

    typed links

    Products, code areas, tickets, PRs, sessions, records and docs in one connected map. Follow a fact back to where it came from, and forward to what it affects.

    • Typed links: about, found in, worked on, changes, resolved by, replaces.
    • Open any code area to see its insights, workflow findings, open gaps and recent work.
    • An insight is flagged for review when later PRs change the code it's about, so stale knowledge doesn't linger.
    • The assistant follows these links as well as searching text, which keeps its answers specific.

    For anyone tracing why something is the way it is.

  • Ask Strata

    chat assistant

    A chat assistant that answers from approved records and the knowledge graph, cites every claim, and says when it doesn't know. It's the main way new joiners find their feet.

    • Onboarding: a first-week path for each product: the overview, local setup, the insights that catch people out, and whom to ask.
    • Status: “What changed in billing this week?” answered from What's new, with links.
    • How and why: workflow findings and insights, each with its source.
    • Answers only from what the person asking is allowed to see.
    • A question it can't answer becomes a context gap, or counts toward one that's already open.
    • The same answers inside Claude Code, through strata_search.

    For new joiners first, and anyone with a question about a product.

Four journeys

How the capabilities fit together for the people who use them most.

PM or executive

Monday status, without a standup

  1. The weekly digest arrives: what shipped and what's in progress, for each product you follow.
  2. Open a product page and read What's new.
  3. Open a line to see its PR, its ticket and the reviewed session summary behind it.
  4. Ask a follow-up: “Why did the invoice timeout move into config?”
New joiner

Productive in the first week

  1. Ask the assistant where to start, and get a first-week path for the product.
  2. The first Claude Code session starts with the product overview, the workflow findings and the open gaps.
  3. Local setup works first time, because the workflow findings cover what the README leaves out.
  4. A question nobody can answer yet becomes a context gap, with someone to own it.
Team or platform lead

Fix the biggest time sink

  1. Open Where engineering time goes: hours lost this month, ranked.
  2. Open the top item and read the sessions and pain points behind its 38 hours.
  3. File it as a ticket from the page.
  4. After the fix ships, the trend shows whether the hours came down.
Tech lead or doc owner

Close a context gap

  1. See the gaps that agents and people hit most, and how often each comes back.
  2. Take ownership of “Why does the job queue deliver at least once?”
  3. Write the ADR and link it. The gap is marked resolved.
  4. New sessions start with the answer, and the gap stops coming back.

How it plugs into Claude Code

Strata ships as a Claude Code plugin. Five hooks do the capture; commands and MCP tools cover review and search.

HookFires whenWhat Strata does
SessionStartA session starts or resumesLoads the product overview and open context gaps, so the agent starts with what earlier sessions learned. Records the repository, branch and commit.
PostToolUseA tool call finishesRecords how long the tool ran and whether it worked. For a shell command, also its kind (test, build, lint…), its exit code and a fingerprint to count re-runs. Never the command text or its output.
StopClaude finishes a responseCaptures Claude's reply, redacted, for the session draft, and the branch or commit if either changed.
PreCompactBefore the conversation is compactedCaptures the transcript before detail is summarized away.
SessionEndThe session closesCloses the session. The server drafts its summary and findings for your review.

A thin adapter that maps opencode's session events onto the same capture core. Same records, same review queue, same sync.

Capture, redaction, the review queue and sync live in one shared core. Each runtime adds only an adapter, so a record looks the same whichever tool produced it.

Ground rules

Visibility into the work, not the worker.

  • Raw text stays private and expires. Prompts and replies, redacted, are only ever their author's, and are deleted after 30 days. What others see is only what you approve.
  • Redaction at source. Secrets are stripped on your machine before anything leaves it, and again on the server.
  • You see what others see. Every record is yours to edit or discard first.
  • About code and process. Pain points and gaps never name or rate a person.
  • No activity logs. No keystrokes, no idle time, and no prompt history past 30 days. Friction hours come from test, build and install runs, never from a person's time.
  • Not for ratings. Records are never used in performance reviews.
  • Who, never how much. Pages show who has worked on an area recently, never counts, rankings or comparisons of people.
  • Answers show their sources. The assistant answers only from approved records, cites each one, and says when it doesn't know.
